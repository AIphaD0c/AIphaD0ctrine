# Roadmap

## Phase 0 — Domain definition

- establish naming and canon
- define ethical boundary
- define agent interfaces
- create engine-neutral project skeleton

**Current phase.**

## Phase 1 — Concert grammar

- analyze licensed and openly usable concert material
- extract visual, audio, motion, and crowd features
- build a concert dramaturgy ontology
- validate temporal beat detection

Deliverable: timeline analysis and direction reports.

## Phase 2 — First-person reconstruction

- create performer-POV scene prototypes
- test hand, instrument, microphone, and body continuity
- compare flat-screen, VR, and spatial-video prototypes

Deliverable: five-minute embodied performance prototype.

## Phase 3 — Responsive stadium

- model crowd causality
- generate stage-scale environmental response
- connect sound, lights, crowd, and participant movement

Deliverable: real-time stadium loop responding to participant behavior.

## Phase 4 — Identity and memory

- implement explicit consent and calibration
- develop gradual identity transition
- create memory salience and afterimage systems
- add post-session reorientation

Deliverable: complete controlled identity-transfer session.

## Phase 5 — AIphaD0m transmission

- integrate AIphaD0c signal catalogue
- create track-specific domains
- define release protocol
- conduct safety and rights review

Deliverable: first public AIphaD0m experience.

## Exit criteria for v1.0

AIphaD0m v1.0 must demonstrate:

- stable first-person embodiment
- causal crowd response
- coherent concert dramaturgy
- explicit consent and safe exit
- no unauthorized real-person imitation
- engine-independent session plan
- reproducible source provenance
